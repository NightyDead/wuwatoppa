桌宠助手

双击“启动.cmd”，在同一个窗口中操作连点器、宝箱自动领取和运行计划。
外层只需使用启动入口；脚本、模板、测试和日志均收在“程序”文件夹中。

界面

1. 左侧是导航栏：连点器、自动领取、运行计划、领取记录、外观设置，点击切换页面。
   五个页面在启动时一次建好，换页只换显示，不重建界面，不会闪。
2. 窗口宽于约 820 像素时导航显示“图标 + 文字”；窄于这个宽度自动收成纯图标，
   字号和布局密度改变时也会自动重排。标题、副标题、字段、分隔线、按钮行都按同一
   套间距排布，字号选“大”时整体等比放大。
3. 页面内容放在半透明面板上。面板下方是“运行日志”开关和最近一条提示；点开后
   日志高度按窗口自动计算，收起后内容区自动补满。页脚左侧显示两项任务的状态，
   右侧是“全部停止”和 Ctrl + Alt 提示（Ctrl + Alt 由子任务自己响应）。
4. 窗口不显示系统标题栏，右上角“– / □ / ✕”分别是最小化（收进通知区域）、
   最大化（还原）和关闭；拖动侧栏、页头或页脚空白处可移动窗口，双击切换最大化。
   从任意一条边或四角拖动都能缩放（最小 660×520），右下角斜纹也是缩放提示。
5. 启动时窗口先保持透明，壁纸排好后在 360 毫秒内淡入，不会先看到空窗。
   最大化按当前屏幕可用区域铺满（已避开任务栏），还原时回到原来的尺寸和位置。
6. 点“–”把窗口收进通知区域；单击通知区域图标即可恢复，右键可选“显示窗口”
   或“退出桌宠助手”。

连点器

1. 填写操作次数、操作间隔和运行时长，点“开始连点”。
   次数 0～100000（0 表示不限），间隔 0.0001～60 秒，时长 0～1000 小时
   （0 表示不限）；两项都填时先到先停，至少填一项。默认 2000 次、0.1 秒、0 小时。
   连点器通过 F15 功能键累积桌宠操作次数。
   连点器与自动领取是两项独立任务：只在连点器栏点“开始连点”就只发 F15，
   不截图也不动鼠标；监测正在跑时也可以再启动连点器，任一项结束都不会停掉另一项。
   桌宠以管理员权限运行时 F15 也会被 Windows 拦截，请看后面的“权限”一节。
2. 自动领取：填写运行时长（小时）和检查间隔（分钟），点“开始监测”。
   “高级设置”里可填“间隙连点”次数（0 表示不连点）和间隔：每轮领取结束后，
   先在等待间隙发送这批按键，再等到下一个检查点。
   成功领取后，从本轮最后一次成功点击松开鼠标的时刻开始计算下次检查时间。
   例如 8 小时、每 30 分钟检查、间隙连点 2000 次：
   领取 → 连点 2000 次 → 等待这 30 分钟内的剩余时间 → 再检查，循环到运行时长上限。
   连点与检查是同一线程上按顺序做的：这批连点没发完就不会开始下一轮；
   即使连点总时长超过检查间隔，也只是下一轮顺延，不会两份连点同时按键。
   监测点宝箱的那一下会短暂移动光标（约 0.4 秒）再还回原处；这期间自己正按着
   鼠标键时，本轮会自动跳过等下一轮，不会和手动操作抢。
3. 页面中间实时显示“已领取 N 个”、当前状态和距离下次检查/结束的剩余时间；
   计数来自子任务上报，最终以桌宠内显示为准（页脚有小字提示）。
4. 每项任务都有独立的“停止”按钮；“全部停止”可停止所有运行中的任务，
   子任务自身也响应 Ctrl + Alt。
5. 关闭窗口时会先安全停止任务，等子任务真正退出后才结束进程，避免遗留按下状态；
   任务全部停止后自动恢复系统的电源设置。任务运行期间会阻止系统休眠和息屏。
6. “工具 ▾”菜单里有：一键同时启动、识别预览（不点击）、测试连点 10 次、
   测试领取一个宝箱、检查运行环境、打开诊断图片目录。
   单次领取测试与持续领取监测不能同时运行，避免重复点击。
   只有填了间隙连点才要求“只启动监测”；间隙连点留空（0）时，
   连点器与监测可以各点各的“开始”，也可以用“一键同时启动”。
   已经带着间隙连点跑起来的监测会一直连点，即使把输入框改成 0 也照样拦住连点器。

运行计划

1. 用“添加连点”或“添加领取”建立任务列表；表格分“序号 / 任务 / 参数”三列，
   每个步骤在弹窗里单独填参数并即时校验；可用“编辑/上移/下移/删除/清空”调整。
2. 点“执行计划”按列表顺序逐个运行：上一步正常结束后自动启动下一步。
   例如第 1 步“自动领取 1 小时”，第 2 步“连点 5000 次”，领取到达 1 小时后自动连点。
3. 当前步骤被手动停止（独立停止按钮、Ctrl + Alt、“停止计划”）或异常退出时，
   计划立即结束，不会启动后续步骤；“全部停止”和关闭窗口也会停止整个计划。
4. 计划保存在“程序/设置.json”，下次启动继续保留；计划运行期间不能修改步骤，
   也不能单独启动任务。

领取记录

1. 自动领取每确认一个宝箱就把本轮计数写入“程序/collector/领取记录.json”，
   最多保留最近 20 次；记录在领取后及结束时保存，异常中断也能留下已确认的数量。
2. “领取记录”页列出开始时间、结束时间、宝箱数和状态（正常完成 / 已停止 /
   异常结束 / 未记录结束）。“未记录结束”可能仍在运行，也可能关闭前没写入结束状态。
3. 点“刷新记录”重新读取；正在运行的监测会同时更新页面上的实时计数。

外观设置

1. 所有改动即时预览；只有点“保存外观”才写入“程序/设置.json”并沿用到下次启动。
   “取消修改”丢弃本次预览，“恢复默认”回到出厂外观。
2. 主题提供金色、深色、浅色；字号小/标准/大；布局密度标准/紧凑。
   “运行日志”可直接选择收起或展开。字号同时决定所有控件的间距与高度。
3. “强调色”和“面板底色”可分别“选择颜色”；“跟随主题”清除自定义颜色。
4. 面板不透明度 30%～100%，整窗不透明度 60%～100%，背景亮度 50%～150%。
   面板只影响底色透明度；整窗不透明度连文字一起透出桌面。滑块下方的百分比即时更新。
5. “背景图片”可选任意 PNG/JPG/WebP，会压缩成 JPEG（不超过 2 MB）保存到
   “程序/外观资源/背景.jpg”；原图移走或删除都不影响显示。“移除背景”改用纯色。
   “显示方式”可选“填充”（铺满，可能裁边）或“适应”（完整显示，可能留边）。
6. 字体默认使用自带的“文鼎方新书”（程序/fonts）。也可以“加载本地字体”选择
   TTF/OTF，或“使用已安装字体”从系统字体中挑一个；下方会显示实际生效的字体和预览。
   字体只在本进程内加载，不安装到系统；取消修改或退出后自动卸载。
7. 窗口位置、大小、当前页面和外观一起保存在设置里，下次启动沿用。
8. “主题方案”在外观页最上方：调好颜色、透明度、壁纸后点“另存为主题”起个名字，
   这套外观（连同当时那张壁纸）就存进设置；换别的方案后再选中它点“应用主题”，
   立即切回并写入设置。同名保存会询问是否覆盖；“删除主题”只删方案，不改当前外观。
   最多存 24 套，名称最多 24 个字。
9. “任务栏图标”只影响点“–”最小化之后：选“显示”时窗口最小化到任务栏，点任务栏
   按钮或通知区域图标都能回来；选“隐藏”时收进通知区域，任务栏不留按钮。通知区域
   图标不可用时一律最小化到任务栏，避免窗口找不回来。

宝箱监测

宝箱监测保留 v4.8 的领取记录与界面同步、v4.7 的间隙连点，以及 v4.6 的
50%～200% 尺寸匹配、位置缓存、局部截图和全屏回退；v4.9 起桌宠缩到 50%～100%
（状态栏图标只剩十来个像素）时也能认出宝箱；v5.0 起状态栏“≡”与宝箱气泡缩放
比例不一致时照样能认（桌宠换皮肤或调大小时两者未必同比例），与桌面背景无关。
宝箱仍受桌宠本身的冷却限制，每个宝箱最多尝试 5 次；实际领取以桌宠内显示为准。
运行日志最多保留最近 1200 行，长时间监测也不会拖慢界面。

权限（点不到宝箱或桌宠不计数时先看这里）

1. 如果桌宠（WuwaTappo.exe）以管理员权限运行，Windows 会拦截普通权限的助手发出的
   鼠标点击和 F15 按键：能识别到宝箱却点不动，连点器也看不出效果。这是系统级的权限隔离，
   不是识别或计数问题。
2. 启动领取或“检查运行环境”时，日志第一行会写明双方权限，例如
   “运行权限：普通用户；桌宠以管理员权限运行，Windows 会拦截本助手发出的鼠标点击”。
   源码版可双击“以管理员身份运行.cmd”，或右键“启动.cmd”选择“以管理员身份运行”。
3. 打包版“桌宠助手.exe”启动时会由 Windows 请求管理员权限，确认后即可运行。
   桌宠以普通权限运行时，源码版可直接双击“启动.cmd”。
4. 为什么“光标会跑过去、F15 也能计数，但就是点不下”：光标的移动和键盘状态是
   整个桌面共享的，所以看得见效果；而鼠标按下/松开必须投递给桌宠窗口，
   正是这一步被系统拦掉。实测普通权限的助手向桌宠窗口发消息会被系统以
   “拒绝访问（错误码 5）”打回，向普通窗口发同样的消息则正常。
   日志里会出现“点击已经发出，但桌宠没有反应：桌宠以管理员权限运行，本助手没有”，
   看到它就是这个问题。

识别不到宝箱（宝箱明明在屏幕上）

1. 先看“工具 ▾ → 识别预览（不点击）”：它会截一张当前屏幕并画框，绿框是认到的宝箱，
   红框是认到了但那个位置不属于桌宠，预览图下面同时给出截图尺寸和系统缩放。
2. 分辨率和缩放不用特意设置：1920×1080、100% 缩放下验证正常，125%/150% 也能用，
   截图按物理像素处理，与缩放无关。
3. 桌宠大小 50%～100% 都能识别。桌宠缩小时状态栏的“≡”只剩十来个像素，v4.8 会因此
   把整只桌宠当成“没有菜单”，宝箱再清楚也报不出来；v4.9 改用“图标偏弱时由高分宝箱
   气泡兜底”，不再卡在这一步。
4. 换个桌面背景后认不出来，多半不是背景的问题：状态栏“≡”和宝箱气泡的缩放比例
   可能不一致（v5.0 之前只按“≡”那一档比例找气泡，偏小时两个都漏掉）。v5.0 起
   会把相近尺寸、两个主题的气泡图样都试一遍，并在局部复查时放宽搜索窗口。
5. 冷却中的宝箱图标是灰的，本来就不该被认成可领取；如果预览里宝箱没有任何框，
   保留“程序/collector/preview.png”方便排查。

程序文件

程序/launcher.py：主界面、窗口行为和任务调度入口（PySide6 版）。
程序/appearance.py：外观默认值、主题调色板、设置校验与原子写入。
程序/ui_state.py：解析子任务上报的已领取数、下次检查与剩余时间。
程序/font_support.py：自带/本地字体的加载、预览、提交与回滚。
程序/ui_theme.py：壁纸导入与缓存、面板透明度、圆角与任务栏按钮。
程序/ui_widgets.py：全局样式表与自绘控件（面板、分隔线、导航项、窗口按钮）。
程序/jobs.py：两项任务的启动、停止、参数校验与运行计划调度。
程序/clicker：连点器及原有测试入口。
程序/collector：自动领取、图标模板、领取记录、识别预览和诊断记录。
程序/fonts：自带的文鼎方新书字体。
程序/背景：默认背景“背景.png”。
程序/外观资源：更换背景后保存的“背景.jpg”（第一次更换时创建）。
程序/外观资源/主题：另存为主题时各自的壁纸副本，删除主题会一并删除。
程序/collector/领取记录.json：最近 20 次监测的领取数量与状态（第一次监测时创建）。
程序/设置.json：界面参数、运行计划、外观设置和保存的主题方案。
程序/runtime：用于通知子任务安全停止，结束时会清理本次停止信号。
以管理员身份运行.cmd：以管理员权限重新启动助手（桌宠已提权时使用）。
桌宠助手.spec：PyInstaller 打包配方，只在打包时用，日常运行不需要。

依赖为 PySide6-Essentials（本机验证 6.8.3）、Pillow，领取识别另需 NumPy（不需要 SciPy）。
启动.cmd 优先使用 D:\anaconda3（或 D:\Anaconda）下的 python/pythonw，找不到就用 PATH 里的。
PySide6 6.12 在本机因 MSVC 运行库过旧无法加载，升级前请先确认能正常导入。
保留完整“桌宠助手”文件夹；不要单独移动“启动.cmd”。

分享主题和迁移设置

在「工具」菜单选择「分享主题」，可导出当前已保存外观或指定主题。主题包包含壁纸
和自定义字体，不包含运行参数。导入后，在「外观设置」里选择并应用；同名主题会另存。

「导出完整设置」还会包含连点与领取参数、运行计划、当前外观和所有主题。导入完整
设置前会提示确认，正在运行的任务须先停止。领取记录、日志和窗口位置不随包迁移。

旧版没有导出按钮时，在新版选「导入主题或设置」，打开旧版原目录里的「设置.json」。
源码版通常在「程序」文件夹里，打包版在「_internal」文件夹里。旧版设置旁边的
外观资源会一起迁移；缺失或位于旧版目录之外的资源会提示使用默认项。

打包成 exe

在干净的虚拟环境里打包，不要用 Anaconda：它的 NumPy 会额外带进约 500 MB 的 Intel MKL 运行库。
  python -m venv 打包环境
  打包环境\Scripts\python -m pip install PySide6-Essentials==6.8.3 pillow numpy pyinstaller
  打包环境\Scripts\python -m PyInstaller --noconfirm --clean 桌宠助手.spec
默认产出文件夹版（启动快，实测约 1.2 秒出现窗口）；设环境变量 PET_ONEFILE=1 则产出单文件版
（体积小，每次启动先解压，明显更慢）。实测文件夹版约 104 MB，单文件版约 46 MB。

发给别人

把 dist\桌宠助手 整个文件夹压成 zip 发过去。解压后双击“桌宠助手.exe”，
确认 Windows 的管理员权限提示即可运行，无需安装 Python。
不要只发 exe：_internal 文件夹里是运行库、字体和识别模板，必须和 exe 放在一起。
设置、领取记录和日志都写在文件夹内部（_internal\设置.json、_internal\collector\领取记录.json），
所以请解压到桌面、文档等可写位置，不要放进 Program Files。
连点器和自动领取由同一个 exe 以 --job 参数在后台启动，不会重复打开主界面。
exe 没有数字签名，对方第一次运行如果出现“Windows 已保护你的电脑”，点“更多信息”→“仍要运行”即可。
